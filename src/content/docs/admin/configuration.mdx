Most day-to-day settings live in the panel UI. A handful of infrastructure
variables must be set in the compose environment before the backend starts;
everything else can be managed from the panel.

## Change a setting in the UI

This is always the first place to look. Every screen below validates input and
saves immediately — except **Admin → Environment**, which asks for a restart
when a change needs one.

| Screen | What it controls |
| --- | --- |
| **Admin → System** | SMTP email, mod manager API keys (CurseForge/Modrinth), default interface language, and **Auto Updater** |
| **Admin → Security** | Rate limits, email verification, lockout policy, file-upload limits, and the panel MCP endpoint |
| **Admin → Environment** | Every environment variable the backend reads, with its source and a restart prompt when required |
| **Admin → Theme** | Panel identity (panel name, logo, favicon), brand colors, surfaces, and custom CSS |
| **Admin → Databases** | MySQL hosts used to provision databases for servers, plus Catalyst database health |
| **Admin → Plugins** | Installed plugins and marketplace |
| **Profile** | Your own language, password, passkeys, and API keys |

## Mod manager API keys

**Admin → System → Mod Manager API Keys** stores the keys the Mod Manager uses
to search and download mods, datapacks and modpacks. Keys are write-only in the
panel: once saved, only the last four characters are shown.

1. Open **Admin → System**, section **Mod Manager API Keys**.
2. Paste the key into **CurseForge API Key** and/or **Modrinth API Key** and
   save.
3. Ask a user to open the Mod Manager tab and confirm the provider appears in
   the provider selector.

CurseForge requires a key for every request. Modrinth is hidden from the
provider selector when its key is empty, so an unconfigured Modrinth key looks
exactly like "the provider does not exist" rather than an error. If a user
reports that a provider is missing from the Mod Manager, check this section
first.

A key shared by many servers is rate limited by the provider; heavy use shows
up as search returning fewer results or downloads failing intermittently.

## Environment variables in the panel

**Admin → Environment** lists every variable the backend reads that does not
already have its own settings page. Values saved there are stored in the
database and applied on the next panel start; when a change needs a restart the
panel prompts the signed-in admin with a **Restart panel** button. **Reset to
.env** removes the override and falls back to the compose value.

Settings with a dedicated editor are left out of this page so each value has one
place to change it: the panel name under **Theme**, rate limits and console
output under **Security**, update automation under **System → Auto Updater**,
OIDC providers under **Theme → Advanced**, and marketplace sources in the plugin
marketplace.

A few variables must stay in `catalyst-docker/.env` because the backend needs
them before it can reach the database (they are shown read-only in the panel):
`DATABASE_URL`, `NODE_ENV`, `PORT`, `POSTGRES_PASSWORD`, `TZ`, and `WORKERS`.
`REDIS_PASSWORD` is **not** in this set — the backend reads it when it connects
to Redis, so it can be set from **Admin → Environment** like other settings.

For those, edit `.env` and recreate the backend container:

```bash
cd catalyst-docker
nano .env
docker compose up -d
```

## Environment reference

- The stack's variables live in `catalyst-docker/.env`; the annotated template
  is `catalyst-docker/.env.example`. The backend's own registry
  (`catalyst-backend/src/lib/env-registry.ts`) lists every variable it reads,
  and **Admin → Environment** renders that registry.
- Docker ports and their defaults: `FRONTEND_PORT=0.0.0.0:8080`,
  `BACKEND_PORT=127.0.0.1:3000`, `POSTGRES_PORT=127.0.0.1:5432`. **Redis is
  published on `127.0.0.1:6379` (loopback only) by default** — the compose
  default `REDIS_PORT` is `127.0.0.1:6379`, and commenting it out does not
  unpublish the port. To make Redis fully internal to the Docker network, add a
  `ports: []` override for the `redis` service. See [networking](/admin/networking/).
- `PUBLIC_URL` is the single source of truth for the panel URL — it drives CORS,
  auth origins, and email links, and the installer derives `PASSKEY_RP_ID` from
  its hostname. Set it here; [networking](/admin/networking/) covers the TLS and
  proxy side.
- Re-run the installer's prompts to regenerate a configured `.env`:
  `bash install.sh --reconfigure` ([installation](/admin/installation/)).

## Rules

1. **Do not edit the database by hand.** Every supported change has a UI field,
   an API endpoint, or a documented variable. Raw SQL edits bypass validation
   and break upgrades ([updating](/admin/updating/)).
2. **Keep secrets out of chat and screenshots.** Database passwords, API keys,
   and node tokens live in your compose `.env`, never in docs or tickets.
3. **Record what you changed.** A one-line note (what, when, why) saves hours
   during the next incident.
