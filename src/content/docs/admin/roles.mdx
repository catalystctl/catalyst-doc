**Roles** are named bundles of permissions; users get powers through roles, not
one-off grants. Manage them under **Admin → Roles**.

## Create a role

1. Open **Admin → Roles** and select **Create role**.
2. On **Details**, set a **Name** (for example `Support L1`) and a
   **Description**.
3. On **Permissions**, optionally start from a **Quick start from a preset** —
   **Administrator**, **Moderator**, **Support**, or **User** — then tick the
   individual permissions. They are grouped by category (Server, Node, File
   Management, Console, Backup, User Management, and so on), and the search box
   filters by name.
4. On **Node Access**, choose which nodes members of this role can see. This is
   visibility, not permission.
5. On **Scoped Access**, leave **No scoped access** for a global role, or grant
   the selected permissions only **By node** or **By server**, so members act
   like bulk subusers on those targets.
6. Select **Save changes**. The role is listed immediately; assign it to a user
   under **Admin → Users**.

**Edit role** reopens the same form. Deleting a role removes its permissions
from every member, so reassign affected users first.

The **Full Administrator Access** card marks a role whose wildcard permission
grants everything; do not hand that out casually.

## Design principles

1. **Least privilege.** Start from nothing and add what the job needs. It is
   easy to grant more later; it is hard to un-see leaked data.
2. **Job-shaped roles.** `Support L1` (view servers, restart, read logs),
   `Billing` (view users, no server control), `Node operator` (nodes only).
   Avoid one giant `Staff` role.
3. **Separate read from write.** Most incidents come from write access that was
   only ever needed for reading.
4. **Review quarterly.** Roles accrete permissions; audit who has what and trim.

## API keys follow the same model

Admin-created [API keys](/api/authentication/) carry scoped permissions from
the same catalog — a monitoring key gets read-only metrics, not server control.
The permissions catalog endpoint documents every available scope.

## Dangerous combinations

- User management + server file access can become full account takeover paths.
- Backup restore + subuser creation can exfiltrate other users' data.
- When a role needs a risky permission, time-box it: grant, do the task, revoke.
