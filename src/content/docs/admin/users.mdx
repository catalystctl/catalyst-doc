Manage accounts under **Admin → Users**.

## Create an account

You need `user.create`. Select **Create user** and work through the wizard:

1. **Account** — **Username**, **Email**, **Password** (minimum 8 characters).
2. **Roles & Servers** — assign one or more **Role**s and, optionally, direct
   server access.
3. **Node Access** — grant the account scoped access to specific nodes, or skip.
4. Select **Create user**.

**Edit user** reopens the same form with an extra **Security** step for the
account's two-factor state; leaving the password blank keeps the current one.

## Find and act on users

- Search by name, email, or ID, and filter by **Role** or **Status** (**Active**,
  **Banned**, **Unverified**).
- **View details** shows the account, roles, server access, **Two-Factor
  Authentication**, **Passkeys**, and **Linked Accounts** state, with actions to
  **Wipe 2FA**, **Wipe all** passkeys, **Unlink** an SSO account, or **Enforce**
  2FA.
- Select users to act in bulk: **Ban**, **Unban**, **Verify Emails**, or delete.
  Banning and deleting are destructive; a user who still owns servers cannot be
  deleted.

Server sharing between players does **not** need admin help — owners send
invites and add [subusers](/users/subusers/) themselves from the server's
**Users & Access** view.

## Admin discipline

1. **Few admins.** Admin rights bypass every limit in the system. Most staff
   need a scoped [role](/admin/roles/), not admin.
2. **Named accounts only.** No shared `admin` login — shared logins make the
   audit log useless and revocation impossible.
3. **Offboard promptly.** Disable accounts when staff leave; their API keys and
   sessions should die with the account — verify this in the audit log.
4. **Strong auth.** Enforce strong passwords; enable whatever MFA/SSO the panel
   offers (see [security](/admin/security/)).

## When users cannot log in

1. Confirm the account exists and is not suspended; check **Status** in
   **Admin → Users**.
2. Reset the password or **Verify email** from the user's detail view.
3. Check mail delivery if invites or resets never arrive (see
   [panel issues](/troubleshooting/panel/)).
4. In **Admin → Audit Logs**, filter the action **Sign-in failed** or the
   resource type **Login lockout** before resetting anything.
