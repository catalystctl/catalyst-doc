## Pagination is per-endpoint, not universal

Catalyst does **not** use one pagination scheme everywhere. Before writing
generic page-walking code, check the endpoint in the
[API reference](/api/reference/). The patterns in use:

### `page` + `limit` with a `pagination` block

`GET /api/admin/users`, `GET /api/admin/servers`, and `GET /api/alerts` return
the collection plus a `pagination` object:

```json
{
  "servers": [ ... ],
  "pagination": { "page": 1, "limit": 20, "total": 84, "totalPages": 5 }
}
```

| Endpoint | `page` default | `limit` default |
| --- | --- | --- |
| `GET /api/admin/users` | 1 | 20 |
| `GET /api/admin/servers` | 1 | 20 |
| `GET /api/alerts` | 1 | 25 |

These endpoints also accept endpoint-specific filters such as `search`
(`/api/admin/users`, `/api/admin/servers`), `status`, and `owner`
(`/api/admin/servers`).

```bash
curl -H "Authorization: Bearer $CATALYST_API_KEY" \
  "https://panel.example.com/api/admin/servers?page=2&limit=50&search=survival"
```

### `page` + `limit` with flat counts

`GET /api/servers/:serverId/backups` returns `backups` plus flat `total`,
`page`, `pageSize`, and `totalPages` fields. `page` defaults to 1 and `limit`
to 50, capped at 100.

### `limit` + `offset` returning `{ success, data }`

`GET /api/servers` uses an offset cursor instead of pages:

```bash
curl -H "Authorization: Bearer $CATALYST_API_KEY" \
  "https://panel.example.com/api/servers?limit=50&offset=100"
```

```json
{ "success": true, "data": [ ... ] }
```

`limit` defaults to 50 (max 100); `offset` defaults to 0. `GET /api/templates`
accepts optional `limit`/`offset` in the same shape — and returns **all**
templates when `limit` is omitted.

### Full lists

Some collections are returned whole and ignore pagination parameters: nodes,
locations, nests, roles, and server allocations. Do not assume `total` or
`pagination` is present on those responses.

## Rules

- **Cap your `limit`.** Ask for what you will display (20–100). Full exports
  belong in bulk endpoints or repeated pages, not `limit=100000`.
- **Paginate to exhaustion** (`page++` until a short/empty page, or advance
  `offset` by the number of rows returned) rather than assuming a total —
  totals shift while you read.
- **Treat pages as snapshots.** Items created or deleted mid-walk can shift
  offsets; for sync jobs, prefer filtering by updated time where offered and
  reconcile.
- **Cache sparingly.** Lists change constantly (server states, node health).
  Cache seconds, not hours, or re-fetch on user action.
