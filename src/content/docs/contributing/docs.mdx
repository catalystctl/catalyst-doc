## Prerequisites

- A local clone of the docs repository (this site's source).
- Node.js ≥ 20 and pnpm. The repository pins `pnpm@9.15.9` via
  `packageManager`; CI installs `pnpm@latest`.

## Edit

Docs are Markdown/MDX under `src/content/docs/`, organized by audience:
`getting-started/`, `users/`, `admin/`, `api/`, `troubleshooting/`,
`contributing/`. Every page except the splash `index.mdx` needs all six
frontmatter fields:

```yaml
---
title: Creating Backups
description: One line saying what the page teaches.
audience:              # user, admin, developer — first entry is the primary audience
  - user
features:              # one or more tags from the canonical vocabulary
  - backups
sources:               # repo paths whose changes should trigger review
  - catalyst-backend/src/routes/backups.ts
last_verified: '2026-09-28'   # bump only when you verify against source
---
```

Rules: task-oriented prose, one **primary** audience per page (the first
frontmatter entry — add further audiences only when the task genuinely spans
them), Catalyst terminology (`panel`, `node`, `server`, `template`, `allocation`, `task` — never reuse the Pterodactyl product name for a Catalyst server, and never call a server a *container* or an *instance*: *container* only means the Docker/OCI runtime object), no invented flags/ports/defaults.

- `features` must use the canonical 30-tag vocabulary listed in `AGENTS.md`.
  `scripts/validate-docs.mjs` hard-fails an unknown tag, and
  `tools/docs-agent/lib/classify.mjs` matches the same tags when it maps
  changed code paths to pages — an invented tag also drops the page out of
  change→docs mapping, so never invent one.
- `api_tags` is **not** part of the frontmatter contract — do not add it.
- Asides use `:::note[Title]` on one line (no space after `:::`). A spaced
  directive (`::: note`) renders literally and now fails validation. Valid
  kinds: `note`, `tip`, `caution`, `danger`.
- A new page also needs a sidebar entry in `astro.config.mjs`. The sidebar is
  nested (Starlight `items:` groups); nesting does not change URLs.

`scripts/validate-docs.mjs` requires all six fields on every page except
`index.mdx`: a missing/empty `features` or `sources` list, an unknown `feature`
tag, an unknown or duplicated `audience` value, and a missing or malformed
`last_verified` are all hard failures, as is a spaced aside directive. See
`AGENTS.md` for the full conventions.

## Validate

```bash
pnpm install
pnpm dev          # preview at http://localhost:4321
pnpm validate     # links, slugs, frontmatter, assets, OpenAPI, terminology
pnpm test         # docs-agent unit tests
pnpm run build    # the same command Cloudflare Pages runs
```

Fix every failure — CI runs the same checks on every pull request.
`pnpm validate` is the fastest gate while editing.

## API reference

Never hand-edit `api/openapi.json`. Regenerate it from a Catalyst checkout
(`--from-checkout` runs that repo's `openapi:export` script):

```bash
pnpm sync-openapi --from-checkout ../catalyst
```

then commit the result. The Scalar viewer (`api/reference`) renders whatever is
committed.

## The docs agent

For larger sync work, run the docs agent (`tools/docs-agent/`) in `audit`,
`diff`, `feature`, `validate`, or `api` mode. It maps Catalyst changes to
affected pages and opens reviewable changes:

```bash
pnpm docs-agent audit --source-repo ../catalyst --docs-repo .
pnpm docs-agent diff --source-repo ../catalyst --docs-repo . \
  --base origin/main --head HEAD --dry-run
```

`diff` and `feature` write proposed changes into the working tree without
committing; `--dry-run` writes nothing. Details in its README.

## Publish

Merge to `main` → Cloudflare Pages builds and deploys to
`docs.catalystctl.com` automatically. Pull requests get preview deployments.
Deployment details: `DEPLOYMENT.md`.
